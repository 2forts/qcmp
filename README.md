# qcmp — Quantum Comparators Library (Qiskit)

`qcmp` is a **modular and extensible Python library for quantum comparators**, implemented in **Qiskit**.  
Its purpose is to provide a **unified software framework** to implement, test, and compare *all* quantum comparator circuits proposed in the literature.

The library is designed to support **research, benchmarking, and review papers** in quantum arithmetic and comparison circuits.

---
------
--------
## ✨ Features

- 🔌 **Plugin-based architecture**: each comparator is an independent module
- 🔢 Arbitrary bit-width `n`
- ▶️ Simple command-line interface (`python -m qcmp`)
- 🧠 Clean separation between:
  - comparator logic
  - input encoding
  - simulation
  - metrics
- 📊 **Optional metrics module** (can be enabled or ignored)
- 🧪 Ready for unit testing and benchmarking
- 📚 Faithful implementations of published quantum comparator circuits

## 📊 Metrics

`qcmp` includes an **optional structural metrics system** for analyzing the quantum circuit generated by each comparator.

The metrics system can be used to:

- benchmark comparator implementations
- compare proposals from the literature
- study scalability with respect to the operand size
- generate symbolic equations using `N` as the number of bits of each operand
- evaluate the effect of different decompositions of large quantum gates

Metrics are computed on the comparator circuit **before input preparation and backend transpilation**. Therefore, they do not depend on the concrete values of `A` and `B`, the simulator, or the selected hardware backend.

### Available metrics

| Metric | Description |
|---|---|
| `quantum_cost` | Cost of the circuit. One- and two-qubit gates have cost 1. Larger gates use a configurable gate profile or are recursively decomposed. |
| `delay` | Length of the critical path. One- and two-qubit gates have delay 1. Larger gates use their configured delay or are recursively decomposed. |
| `num_qubits` | Total number of qubits in the comparator circuit. |
| `num_auxiliaries` | Number of input qubits that are not used to store the two operands. |
| `num_garbage_outputs` | Number of outputs that are not restored to `0`, restored to an operand, or used to store the solution. |
| `t_count` | Total number of `T` and `Tdg` gates. |
| `t_depth` | Number of sequential T-gate layers in the critical path of the circuit. |

Each comparator declares its operand, solution, and restored auxiliary qubits through a `ResourceLayout`.

### Run a comparator with selected metrics

Metrics are disabled by default. Use `--metrics` with a comma-separated list:

```bash
python -m qcmp run \
  --cmp lt_orts_tand \
  --n 4 \
  --A 1 \
  --B 2 \
  --metrics quantum_cost,delay,num_qubits,num_auxiliaries,num_garbage_outputs,t_count,t_depth
```

To calculate every available metric:

```bash
python -m qcmp run \
  --cmp lt_orts_tand \
  --n 4 \
  --A 1 \
  --B 2 \
  --metrics-all
```

The output includes a `metrics` object:

```json
{
  "cmp": "lt_orts_tand",
  "n": 4,
  "A": 1,
  "B": 2,
  "decoded": {
    "lt": 1
  },
  "metrics": {
    "quantum_cost": "...",
    "delay": "...",
    "num_qubits": "...",
    "num_auxiliaries": "...",
    "num_garbage_outputs": "...",
    "t_count": "...",
    "t_depth": "..."
  }
}
```

The exact values depend on the comparator and on the gate profiles being used.

NOTE: There are some comparators that accept input only through qubits, while the other input is implemented directly through the circuit using quantum gates (these are therefore constant inputs). These comparators can be invoked in a similar way to normal comparators, simply by specifying the values of A and B. The software will handle the implementation of both operators as appropriate. However, you can explicitly specify the constant value as follows:

```bash
python -m qcmp equations \
  --cmp lt_orts_constant_tand \
  --build-kwargs '{"b_value": 7}'
```

It is essential to understand that, in this type of comparison tool, the metrics DO depend on the constant operator's binary pattern.

### Generate metric equations

`qcmp` can evaluate a comparator for several values of `N` and infer symbolic equations:

```bash
python -m qcmp equations --cmp lt_orts_tand
```

For example, the framework detects the following T-depth equation for the temporary-logical-AND comparator:

```text
T-depth = N + 1
```

The equation generator returns:

- the inferred expression
- its polynomial degree
- the valid domain
- the sampled values
- any exceptional values of `N`

Example structure:

```json
{
  "comparator": "lt_orts_tand",
  "equations": {
    "t_depth": {
      "degree": 1,
      "domain": "N >= 1",
      "expression": "N + 1",
      "samples": {
        "1": 2,
        "2": 3,
        "3": 4,
        "4": 5
      }
    }
  }
}
```

Selected equations can be generated with:

```bash
python -m qcmp equations \
  --cmp lt_orts_tand \
  --metrics quantum_cost,delay,t_count,t_depth
```

The equation search can also be configured:

```bash
python -m qcmp equations \
  --cmp lt_orts_tand \
  --sample-max 16 \
  --max-degree 4
```

### Configurable gate profiles

Large gates can define their own resource metrics. The default configuration includes a profile for the three-qubit Toffoli gate:

```json
{
  "ccx/3": {
    "quantum_cost": 5,
    "delay": 5,
    "t_count": 7,
    "t_depth": 3
  }
}
```

The key format is:

```text
gate_name/number_of_qubits
```

Custom profiles can be loaded from a JSON file:

```bash
python -m qcmp equations \
  --cmp lt_xia_cgc \
  --gate-profiles custom_gate_profiles.json
```

The same profiles can be used when running a comparator:

```bash
python -m qcmp run \
  --cmp lt_xia_cgc \
  --n 4 \
  --A 1 \
  --B 2 \
  --metrics-all \
  --gate-profiles custom_gate_profiles.json
```

To inspect the active profiles:

```bash
python -m qcmp gate-profiles
```

An example configuration is provided in:

```text
gate_profiles.example.json
```

### Important note about T metrics

The framework counts explicit `T` and `Tdg` instructions and calculates their critical path.

Parameterized rotations such as:

```python
qc.cp(theta, control, target)
```

are not automatically synthesized into a Clifford+T gate set. For instance, the circuit of Yuan et al., based on QFT and controlled-phase rotations, may report:

```text
T-count = 0
T-depth = 0
```

This means that the original circuit contains no explicit T gates; it does **not** necessarily mean that its fault-tolerant implementation has zero T cost.

To obtain physical Clifford+T metrics for these circuits, the rotations must first be synthesized using a specified approximation precision and synthesis strategy.

## Project Structure

The repository is organized as follows:

- `pyproject.toml` — package metadata and dependencies
- `README.md` — (this file)
- `qcmp/`
  - `__init__.py`
  - `__main__.py` — CLI entrypoint (`python -m qcmp ...`)
  - `encoding.py` — classical integer → basis-state encoding (X gates)
  - `registry.py` — comparator registration + lookup
  - `runner.py` — execution pipeline (prep inputs, transpile, simulate, decode, optional metrics)
  - `result.py` — `RunResult` dataclass
  - `comparators/`
    - `__init__.py` — registers available comparator plugins
    - `base.py` — comparator interface (`ComparatorMeta`, `BuildOutput`)
    - `cmp_oliveira_qbsc.py` — Oliveira and Ramos (2007) full bit-string comparator
    - `lt_orts_tand.py` — Orts et al. (2021) LT comparator (temporary logical-AND based)
    - `lt_xia_cgc` — Xia et al. (2018) LT comparator (CGC gate based)
    - `lt_xia_qip.py` — Xia et al. (2019) half multi-bit LT comparator
    - `lt_yuan_qft` — Yuan et al. (2023) LT comparator (QFT-based)
  - `metrics/`
    - `__init__.py` — metrics registry + implementations (current repo keeps metrics here)
- `tests/`
  - `test_smoke.py` — minimal smoke test

This structure allows new comparators and metrics to be added with minimal changes to the core code.
